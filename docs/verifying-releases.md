# Verifying rhorizon releases

Every git tag matching `v*` (e.g. `v1.0.0`) triggers a release pipeline
that builds, hashes, and cosign-signs every shippable artifact, then
publishes them as Gitea release assets.

## What's published per release

For tag `vX.Y.Z` (https://github.com/JR-Shdw/Horizon/releases/tag/vX.Y.Z):

| Asset | Description |
|---|---|
| `rhorizon_crypto-X.Y.Z-cp312-abi3-manylinux_*.whl` | Rust extension wheel (the only thing not pip-installable from PyPI) |
| `rh-inject` / `rh-fetch` / `rh-watch` | Static musl agent binaries (init-container payload) |
| `terraform-provider-rhorizon_X.Y.Z_linux_amd64` | Go Terraform provider (static, `-trimpath`/`-buildid=` reproducible) |
| `rhorizon-client-X.Y.Z.tgz` | npm SDK pack (`@rhorizon/client`, version from package.json) |
| `rhorizon-X.Y.Z-source.tar.gz` | Deterministic git archive of the tagged commit (includes the vendored `eso-provider` source) |
| `<module>.sbom.cdx.json` | Per-module CycloneDX SBOM (`rhorizon_crypto`, `rhorizon-agent`, `terraform-provider-rhorizon`, `rhorizon-client`) - signed like every other asset and hashed into the provenance subjects |
| `*.sig` | Detached cosign signature (legacy / explicit-key flow) |
| `*.bundle` | Cosign self-contained bundle (signature + cert + payload) |
| `*.sha256` | SHA-256 hash for an extra cross-check |

All assets are signed with the same key that signs Docker images
(`cosign.pub` at the repo root).

## Verifying

```bash
TAG=v1.0.0
BASE=https://github.com/JR-Shdw/Horizon/releases/download/$TAG

# Public key (committed at the repo root, served via Gitea raw)
curl -fsSL https://raw.githubusercontent.com/JR-Shdw/Horizon/main/cosign.pub > cosign.pub

# Pick the artifact you want to verify
ASSET=rhorizon_crypto-1.0.0-cp312-abi3-manylinux_2_34_x86_64.whl

curl -fsSL "$BASE/$ASSET"          -O
curl -fsSL "$BASE/$ASSET.bundle"   -O
curl -fsSL "$BASE/$ASSET.sha256"   -O

# 1. Hash check (cheap sanity step)
sha256sum -c "$ASSET.sha256"

# 2. Cosign signature (preferred - bundle includes the signature payload)
cosign verify-blob --key cosign.pub --bundle "$ASSET.bundle" "$ASSET"
```

`cosign verify-blob` exits non-zero on signature mismatch, missing
file, wrong key, or any tampering. Both the bundle path and the
binary path are required.

## Detached `.sig` flow (explicit signature file)

If you prefer the raw `.sig` over the bundle:

```bash
curl -fsSL "$BASE/$ASSET.sig" -O
cosign verify-blob --key cosign.pub --signature "$ASSET.sig" "$ASSET"
```

Same result; the bundle is just a self-contained envelope.

## Trust roots

The same chain as documented in `docs/verifying-images.md`:

| Artifact | Where | What it proves |
|---|---|---|
| `cosign.pub` | repo root + Gitea raw URL | Anything signed by us is signable only with the matching private key. |
| Private key + password | Woodpecker secrets `cosign_key`, `cosign_password` (node-2) | Independent of rhorizon vault - releasing rhorizon does **not** require rhorizon to be unsealed. |
| Tag -> commit binding | Gitea repo (immutable tags) | Tag `vX.Y.Z` resolves to a specific commit SHA; the release body shows the SHA + the Woodpecker pipeline that built it. |

## Reproducing a release locally

The release pipeline uses `SOURCE_DATE_EPOCH = git commit timestamp`
and `RUSTFLAGS=--remap-path-prefix=...=.` so the artifacts are byte-stable.

```bash
git checkout vX.Y.Z
SOURCE_DATE_EPOCH=$(git log -1 --format=%ct HEAD)

# rhorizon_crypto wheel
docker run --rm -v "$PWD/api/rust:/build" -w /build \
  -e SOURCE_DATE_EPOCH \
  -e RUSTFLAGS="--remap-path-prefix=/build=." \
  python:3.12-slim@sha256:46cb7c... \
  bash -c "apt-get update && apt-get install -y curl gcc libc6-dev && \
           curl https://sh.rustup.rs | sh -s -- -y && \
           PATH=/root/.cargo/bin:\$PATH pip install maturin && \
           PATH=/root/.cargo/bin:\$PATH maturin build --release --locked --strip"

sha256sum api/rust/target/wheels/*.whl
# Should match the .sha256 from the release.
```

The CI gate `.woodpecker/reproducibility.yml` enforces this same
property on every push, so a release build is just a reproducible
build with extra signing + publishing on top.

## Inspect a module SBOM

Each client module ships a signed CycloneDX SBOM. Verify it like any
other asset, then read its component list:

```bash
ASSET=rhorizon-client.sbom.cdx.json
cosign verify-blob --key cosign.pub --bundle "$ASSET.bundle" "$ASSET"

# What's in it (name@version per component):
jq -r '.components[] | "\(.name)@\(.version)"' "$ASSET"
```

The SBOMs are generated by `trivy fs --include-dev-deps --format
cyclonedx` over each module's committed lockfile (`Cargo.lock`,
`go.sum`, `package-lock.json`), so they enumerate the build-time
supply chain, not just runtime deps. The daily `scan.yml` cron runs
`trivy fs` over the same lockfiles for fresh CVEs (reports aggregate
into the scan summary).
