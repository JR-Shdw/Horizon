# Frontend vulnerability-remediation record — 20 October 2026

Scope: **local amd64 frontend image and source fix only**. This record supports
Annex I I-2(a) and II-1/2/3/7; it is not proof of whole-product CRA conformity,
exploitability in a deployed vault, public image availability or all-platform
coverage. [Requirements matrix](../requirements.md).

## Reported findings and change

The supplied scan reported Alpine 3.24.1 with:

| CVE | Reported package version | Fixed minimum required by the Dockerfile |
|---|---|---|
| CVE-2026-77214 | `libexpat 2.8.5-r0` | `libexpat >= 2.9.0-r0` |
| CVE-2026-88806 | `libx11 1.8.13-r0` | `libx11 >= 1.8.14-r0` |

The change in [frontend/Dockerfile](../../frontend/Dockerfile) requires both
minimum versions using `apk add --no-cache --upgrade`. A mirror without the
required packages fails the build. Existing libuuid, PCRE2 and TIFF fixes remain.
The pinned base used in the local rebuild contained libexpat 2.8.4-r0; it was
upgraded directly to 2.9.0-r0. Do not confuse that base-package observation with
the user's previously built 2.8.5-r0 image.

Canonical source commit: `12e0bf96b11a25763a5a6bf2738f68728fd7064b`.
Public source commit:
[`54b6e1358bc787abe10a1641fb90c3ceff23f912`](https://github.com/JR-Shdw/Horizon/commit/54b6e1358bc787abe10a1641fb90c3ceff23f912).
Both commits were SSH-signed and verified locally before pushing.

## Limits and remaining evidence

- The original reported image digest and original raw scan report were not
  supplied. Exact historical affected-image inventory remains open.
- The scan is a point-in-time check for selected severities. It does not prove
  absence of lower-severity exploitable issues, unknown flaws or active attacks.
- No evidence of active exploitation or a severe incident was provided in this
  task. This is not a finding that exploitation never occurred; the PSIRT must
  assess the Article 14 triggers using operational intelligence.
- Full raw build/scan logs and a hashed JSON report were not added to a durable
  evidence archive. Attach release CI reports and their hashes before treating
  this as a complete retained release record.
- The local archive is temporary evidence, not the long-term update repository.
  Record the actual released digests, platform scans, SBOMs, signatures,
  provenance, advisory and retention location separately.
- Existing GHCR policy excludes the frontend image. Its public Dockerfile fix
  is published; API/agent image promotion is a separate action and is not
  evidence that a public frontend image was released.
